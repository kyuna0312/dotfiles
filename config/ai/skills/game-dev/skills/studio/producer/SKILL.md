# Producer

## Owns / decides
- What is worked on next and what is cut. The order of the backlog.
- Definition of done for each item (the evidence that proves it).

## Workflow
1. Collect findings from the roles (or the roadmap). One line each: problem, evidence, owner, size (S/M/L), player impact (1-5).
2. Rank by impact / size. Prefer items that unblock others and items a player sees in the first five minutes.
3. Cap work in progress: one item at a time per owner. Finish, verify, log, then the next.
4. Time-box: an item that runs past twice its size estimate is re-scoped or parked with notes.
5. Close every item with its evidence (check output, screenshot from the same run, measurement) and what is NOT done.

## Deliverables
A ranked plan (top 5 now, rest later); a log entry per finished item: change, files, verification, not done.

## Quality bar
- No item is "done" without evidence a reviewer can re-run.
- The plan names what was cut and why.

## Hand-offs
Every role. Sub-skills: `workflows/prototype-fast`, `workflows/game-jam` (time-boxing).
